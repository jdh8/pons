# Review from Claude Chat

Maybe we need a `bba` system that collects BBA's rules but uses our own
accountant?  The below was my midnight chat with Claude.

- - -

「不確定缺了什麼」這句話本身我覺得是最該先解決的，因為跟 BBA 打輸十幾個 IMP 這個數字幾乎沒有診斷價值——叫牌制度的損失從來不是均勻分布的，通常是幾個洞在漏，而每個洞的修法完全不同。所以在猜缺什麼之前，我會先把 bba-score 的輸出拆開來看損失落在哪裡。幾個我會切的軸：

競爭叫 vs 非競爭叫。 這是最常見的大頭。2/1 的建設性叫牌（開叫 → 應叫 → 再叫 → 定約）是大家都寫得最仔細、資料最齊的部分，BBA 在這裡很難贏你多少；但只要對手一插嘴，手寫 trie 的覆蓋率就會急遽掉下去。可以直接統計：輸的 IMP 裡，有多少是對手有叫過牌的 board？如果超過七成，那問題不在 2/1，在 overcall、balancing、負雙、競爭性加叫、以及最後那個「該不該再叫一級 / 該不該罰」的決定——這塊才是你前面說的「判斷」真正密集的地方。

掉出 trie 的頻率。 每次序列走到沒有定義的節點，fallback 做了什麼？如果是某種「就 pass 吧」或「就叫最接近的」，那每次掉出去平均要賠多少？這個數字乘上頻率，就是「覆蓋率」這條洞的大小。很多時候修這個不需要任何判斷力，只是要把 trie 補完——而這剛好是 LLM 最擅長而人最煩的工作。

終局決定的方向。 把輸的 board 按「我們叫高了 / 叫低了 / 叫錯花色」分類，再對照 DD par。如果系統性地叫高，通常是手牌評估太樂觀——我猜你的評估器是拿 DD 結果校過的，這裡有個陷阱：DD 本來就高估需要猜牌的合約，所以用 DD 校出來的點數法會比實戰偏激進。但你跟 BBA 比也是 DD 計分……那偏激進反而應該是優勢。除非 BBA 也一樣激進，那就不是這條。如果反過來系統性叫低，那大概是 fit 和 shape 的加分不夠，NLTC 或 Zar 本身在不平均牌型上的表現值得分開檢查。

defender 方 vs declarer 方。 一個容易被忽略的來源：你跟 BBA 各坐一邊，但損失可能主要來自你當防家時沒有干擾對方，而不是你自己的建設性叫牌。這跟上面競爭叫那條相關，但角度不同——它問的是「我們的犧牲叫 / 干擾叫夠不夠積極」。

對照條件本身。 bba-score 的 plain 跟 perfect-defense 兩種計分之間差距有多大？如果 perfect-defense 下差距縮小很多，表示一部分「損失」其實是 EPBot 在 DD 下恰好較占便宜的合約類型，不是制度差異。另外 BBA 有自己對 2/1 的詮釋，它的 2/1 跟你寫的 2/1 可能在幾個關鍵約定上（1NT forcing 的範圍、2/1 之後的再叫結構、Bergen 之類）就不一樣，有些差距可能只是約定選擇而非品質。

至於我自己的猜測——如果非要猜缺什麼，我會賭在競爭叫牌裡的「判斷節點」被當成規則寫了。像「對手 2♠ 後我們該 double 還是 3NT」這種決定，手寫 trie 裡只能給一個條件；EPBot 累積了幾十年的 case，它的規則數量大概是你的一個量級以上，而且很多規則本質上是「在這種形狀下，過去的統計說這樣做比較好」的編碼。換句話說，你輸的可能不是聰明，是資料量——BBA 的 trie 更大更密，而這恰好是最適合用自動化（A/B 對打 + 自動補節點）去追的那種差距，不需要等 AI bidder。
